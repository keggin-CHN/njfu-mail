# 05. 网络环境与反爬风控避坑指南 (Anti-Crawler & Environment)

在开发与复用南林邮箱脚本时，最容易遭遇网络超时、连接强行关闭、TLS 握手报错等隐蔽问题。以下为实战中总结的三大关键避坑原则。

---

## 陷阱一：腾讯企业邮箱 TLS 指纹 (JA3) 拦截

### 现象
使用原生 Python `requests`、`urllib` 或 `httpx` 发起请求时，服务器直接抛出异常：
```text
ConnectionResetError: [WinError 10054] 远程主机强迫关闭了一个现有的连接
ssl.SSLEOFError: [SSL: UNEXPECTED_EOF_WHILE_READING] EOF occurred in violation of protocol
```

### 原因分析
南林邮箱托管在腾讯企业邮箱服务集群（IP 如 `14.17.27.155`）。腾讯网关层部署了深度的 TLS ClientHello 指纹识别。标准的 Python OpenSSL 握手报文在 Ciphers、Extensions、GREASE、ALPN 等排列上具有明显的特征，会被腾讯 WAF 直接静默 Reset。

### 解决方案
必须使用 [`curl_cffi`](https://github.com/yifeikong/curl_cffi) 库，并在初始化 Session 时模拟主流浏览器特征（推荐 `chrome116` 或 `chrome120`）：
```python
from curl_cffi import requests
session = requests.Session(impersonate="chrome116")
```

---

## 陷阱二：本地代理软件 (Clash / v2rayN 等) 冲突

### 现象
本地运行了代理客户端（如端口 `10808` / `7890`），且开启了 Windows 系统代理。此时 Python 脚本会报：
```text
curl: (35) TLS connect error: error:00000000:invalid library (0):OPENSSL_internal:invalid library (0)
```

### 原因分析
Python 与 `libcurl` 默认会读取系统的 `HTTP_PROXY` / 注册表代理设置。如果校园邮箱域名（`mail.njfu.edu.cn`）被代理客户端判定为全局路由或境外节点转发，海外节点连接腾讯邮箱国内服务时极易触发安全策略或由于 SOCKS/HTTP CONNECT 失败而重置。

### 解决方案
在初始化 Session 时显式传入 `proxies={"http": None, "https": None}`，强制绕过代理直连：
```python
session = requests.Session(
    impersonate="chrome116",
    proxies={"http": None, "https": None}
)
```

## 陷阱三：高频请求触发 WAF 临时限流 (Rate Limiting)

### 现象
批量扫描 20~30 封邮件时，前十几个请求正常，随后突然连续报错 `(35) TLS connect error`，暂停 1~2 分钟后又自动恢复。

### 原因分析
腾讯网关对单个 IP 的短时间内突发 TLS 握手次数设有限频阈值。如果在单线程中以无休眠（`0s` 间隔）连续并发请求详情和附件，会被判定为爬虫并遭到 30~60 秒的静默封锁。

### 解决方案
1. **请求节流（Pacing）**：在每次抓取详情或附件之间，主动插入 `0.3s ~ 0.5s` 的轻微休眠：
   ```python
   time.sleep(0.4)
   ```
2. **指数退避重试（Retry with Backoff）**：
   ```python
   for attempt in range(3):
       try:
           resp = session.get(url, timeout=10)
           resp.raise_for_status()
           break
       except Exception as e:
           if attempt == 2:
               raise
           time.sleep(2 * (attempt + 1))
   ```
